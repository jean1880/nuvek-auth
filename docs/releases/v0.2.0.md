# v0.2.0

Rust `nuvek-auth` and Vue `@nuvek/auth` advance together to 0.2.0.

## Permission claims

The signed `https://nuvek.ca/permissions` claim supports administrator-controlled grants issued by
an Auth0 Action, including deployments without native API RBAC. The namespace is authoritative
when present, including an empty array. Native `permissions` remain a fallback only when the
namespace is absent. Malformed namespaces fail closed; neither source grants wildcard permissions,
and `scope` never grants permissions. Vue uses the same selection and filtering for its display.

## Optional passkey requirement

`{P}REQUIRE_PASSKEY=true` requires literal `passkey` in signed `https://nuvek.ca/amr` before any OIDC
principal is established, including for protected read routes. It defaults to false. A standard
`amr` claim, an enrolled passkey or an access permission alone cannot satisfy it.

The tenant Action must derive grants and assurance from actual completed authentication, using
administrator-owned `app_metadata` for permissions. Refresh exchanges without proven passkey
provenance receive no grants. Passkeys do not manufacture MFA; the existing MFA policy is unchanged.
Static machine tokens remain exempt from interactive assurance requirements.

## Adoption

Upgrade the Rust git tag and Vue dependency together to `v0.2.0`. Configure and verify the tenant
Action before opting into `{P}REQUIRE_PASSKEY`; incomplete assurance claims reject OIDC access.
Existing native permission deployments retain their behaviour while the namespace is absent and
the new option is disabled.

Validation covers signed JWT claim precedence, malformed claims, signature tampering, protected
reads, independent MFA, machine-token access and Vue permission display.
